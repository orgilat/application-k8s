06File-by-file — full code

Every file, complete, no // ... shortcuts — grouped exactly like the folders on disk. This section alone is enough to recreate the exporter from an empty folder.

apps/automation-results-exporter/ — packaging

package.json

Declares the two runtime dependencies — Express for HTTP, prom-client for metrics — and the three lifecycle scripts every Node service needs.

{
  "name": "automation-results-exporter",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "dev": "tsx src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js"
  },
  "dependencies": {
    "express": "^4.18.3",
    "prom-client": "^15.1.3"
  },
  "devDependencies": {
    "@types/express": "^4.17.21",
    "@types/node": "^20.11.30",
    "tsx": "^4.7.1",
    "typescript": "^5.4.3"
  }
}

What it does: dev runs TypeScript directly via tsx for local iteration; build/start is the compiled path the Dockerfile actually uses.

tsconfig.json

Compiles src/ to dist/ as CommonJS so the built output can run with plain node, no runtime TS compiler needed.

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "CommonJS",
    "moduleResolution": "Node",
    "outDir": "dist",
    "rootDir": "src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts"]
}

What it does: produces the dist/index.js that the Dockerfile's CMD and npm start both run.

Dockerfile

Builds a standalone image for the exporter — installs deps, compiles TypeScript, then runs the compiled output.

FROM node:20-alpine

WORKDIR /app

COPY apps/automation-results-exporter/package*.json ./

RUN npm install

COPY apps/automation-results-exporter/tsconfig.json ./tsconfig.json
COPY apps/automation-results-exporter/src ./src

RUN npm run build

ENV NODE_ENV=production

EXPOSE 3001

CMD ["npm", "start"]

What it does: every COPY is prefixed with the app's full path because the Docker build context is the repo root (context: . in the compose file, §15), not this folder. npm error Missing script: "build" almost always means the build context is wrong and COPY package*.json ./ grabbed the wrong file.

metrics.routes.ts

The actual scrape endpoint — refreshes both metric groups from disk, then renders the Prometheus text format.

import { Router } from 'express';
import { registry } from '../metrics/registry';
import { updateHistoryMetrics } from '../metrics/update-history.metrics';
import { updateLatestRunMetrics } from '../metrics/update-latest-run.metrics';

export const metricsRouter = Router();

metricsRouter.get('/metrics', async (_req, res) => {
  try {
    updateLatestRunMetrics();
    updateHistoryMetrics();

    res.set('Content-Type', registry.contentType);
    res.end(await registry.metrics());
  } catch (error) {
    console.error(
      JSON.stringify({
        level: 'error',
        service: 'automation-results-exporter',
        message: 'failed to generate metrics',
        error: error instanceof Error ? error.message : String(error),
      })
    );

    res.status(500).send('failed to generate metrics\n');
  }
});

What it does: the only place "update metrics" and "read files" get triggered — on demand, per request. There's no background timer; Prometheus's scrape is the trigger for freshness.

src/results/

ctrf-reader.ts

Parses one CTRF JSON file into a normalized result — the only file in the whole exporter that knows what a CTRF report's JSON shape looks like.

import fs from 'fs';

type CtrfReport = {
  timestamp?: string;
  results?: {
    summary?: {
      tests?: number;
      passed?: number;
      failed?: number;
      skipped?: number;
      pending?: number;
      other?: number;
      start?: number;
      stop?: number;
    };
  };
};

export type LatestRunResult = {
  exists: boolean;
  total: number;
  passed: number;
  failed: number;
  skipped: number;
  pending: number;
  other: number;
  durationSeconds: number;
  completedAtSeconds: number;
};

export function readCtrfRunResult(filePath: string): LatestRunResult {
  if (!fs.existsSync(filePath)) {
    return emptyLatestRunResult();
  }

  const rawFileContent = fs.readFileSync(filePath, 'utf-8');
  const report = JSON.parse(rawFileContent) as CtrfReport;

  const summary = report.results?.summary;

  const total = summary?.tests ?? 0;
  const passed = summary?.passed ?? 0;
  const failed = summary?.failed ?? 0;
  const skipped = summary?.skipped ?? 0;
  const pending = summary?.pending ?? 0;
  const other = summary?.other ?? 0;

  const start = summary?.start ?? 0;
  const stop = summary?.stop ?? 0;

  const durationSeconds =
    start > 0 && stop >= start ? (stop - start) / 1000 : 0;

  const completedAtSeconds =
    stop > 0 ? stop / 1000 : getTimestampSeconds(report.timestamp);

  return {
    exists: true,
    total,
    passed,
    failed,
    skipped,
    pending,
    other,
    durationSeconds,
    completedAtSeconds,
  };
}

function emptyLatestRunResult(): LatestRunResult {
  return {
    exists: false,
    total: 0,
    passed: 0,
    failed: 0,
    skipped: 0,
    pending: 0,
    other: 0,
    durationSeconds: 0,
    completedAtSeconds: 0,
  };
}

function getTimestampSeconds(timestamp?: string): number {
  if (!timestamp) {
    return 0;
  }

  const parsedTimestamp = new Date(timestamp).getTime();

  if (Number.isNaN(parsedTimestamp)) {
    return 0;
  }

  return parsedTimestamp / 1000;
}

What it does: called on both latest.json (may not exist on a fresh checkout) and every file under runs/ (could be partially written/corrupt). Missing file → zeroed result, never a thrown error. The caller additionally wraps its own call in try/catch for JSON parse errors.

runs-reader.ts

Scans every file under results/runs/ and aggregates them into totals — the historical counterpart to ctrf-reader.ts's single-file read.

import fs from 'fs';
import path from 'path';
import { readCtrfRunResult } from './ctrf-reader';

type TestStatus = 'total' | 'passed' | 'failed' | 'skipped' | 'pending' | 'other';
type RunStatus = 'passed' | 'failed' | 'other';

export type RunsHistoryResult = {
  runsDir: string;
  runsDirExists: boolean;
  runFilesCount: number;
  parseErrors: number;
  runsByStatus: Record<RunStatus, number>;
  testsByStatus: Record<TestStatus, number>;
  durationSecondsSum: number;
  durationSecondsCount: number;
};

export function readRunsHistory(resultsDir: string): RunsHistoryResult {
  const runsDir = path.join(resultsDir, 'runs');
  const history = createEmptyHistory(runsDir);

  if (!fs.existsSync(runsDir)) {
    return history;
  }

  const runFilePaths = fs
    .readdirSync(runsDir)
    .filter((fileName) => fileName.endsWith('.json'))
    .map((fileName) => path.join(runsDir, fileName));

  history.runsDirExists = true;
  history.runFilesCount = runFilePaths.length;

  for (const runFilePath of runFilePaths) {
    addRunToHistory(history, runFilePath);
  }

  return history;
}

function addRunToHistory(history: RunsHistoryResult, runFilePath: string) {
  try {
    const run = readCtrfRunResult(runFilePath);

    if (!run.exists) {
      return;
    }

    const runStatus = getRunStatus(run.total, run.failed);

    history.runsByStatus[runStatus] += 1;

    history.testsByStatus.total += run.total;
    history.testsByStatus.passed += run.passed;
    history.testsByStatus.failed += run.failed;
    history.testsByStatus.skipped += run.skipped;
    history.testsByStatus.pending += run.pending;
    history.testsByStatus.other += run.other;

    if (run.durationSeconds > 0) {
      history.durationSecondsSum += run.durationSeconds;
      history.durationSecondsCount += 1;
    }
  } catch {
    history.parseErrors += 1;
  }
}

function getRunStatus(total: number, failed: number): RunStatus {
  if (failed > 0) return 'failed';
  if (total > 0) return 'passed';
  return 'other';
}

function createEmptyHistory(runsDir: string): RunsHistoryResult {
  return {
    runsDir,
    runsDirExists: false,
    runFilesCount: 0,
    parseErrors: 0,
    runsByStatus: {
      passed: 0,
      failed: 0,
      other: 0,
    },
    testsByStatus: {
      total: 0,
      passed: 0,
      failed: 0,
      skipped: 0,
      pending: 0,
      other: 0,
    },
    durationSecondsSum: 0,
    durationSecondsCount: 0,
  };
}

What it does: re-scans the whole directory on every call — cheap at the scale of one project's history; revisit only if run history grows very large (rotation, §16 troubleshooting). A run counts failed if ≥1 test failed, passed if zero failures and ≥1 test, otherwise other.

update-latest-run.metrics.ts

Reads latest.json through ctrf-reader.ts and sets the 4 "current state" Gauges.

import { config } from '../config';
import { readCtrfRunResult } from '../results/ctrf-reader';
import {
  automationLastRunDurationSeconds,
  automationLastRunStatus,
  automationLastRunTests,
  automationLastRunTimestampSeconds,
} from './automation.metrics';

export function updateLatestRunMetrics() {
  const latestRun = readCtrfRunResult(config.latestResultsFilePath);

  automationLastRunTests.set(
    { environment: config.environment, status: 'total' },
    latestRun.total
  );

  automationLastRunTests.set(
    { environment: config.environment, status: 'passed' },
    latestRun.passed
  );

  automationLastRunTests.set(
    { environment: config.environment, status: 'failed' },
    latestRun.failed
  );

  automationLastRunTests.set(
    { environment: config.environment, status: 'skipped' },
    latestRun.skipped
  );

  automationLastRunTests.set(
    { environment: config.environment, status: 'pending' },
    latestRun.pending
  );

  automationLastRunTests.set(
    { environment: config.environment, status: 'other' },
    latestRun.other
  );

  automationLastRunDurationSeconds.set(
    { environment: config.environment },
    latestRun.durationSeconds
  );

  automationLastRunTimestampSeconds.set(
    { environment: config.environment },
    latestRun.completedAtSeconds
  );

  automationLastRunStatus.set(
    { environment: config.environment, status: 'passed' },
    latestRun.exists && latestRun.total > 0 && latestRun.failed === 0 ? 1 : 0
  );

  automationLastRunStatus.set(
    { environment: config.environment, status: 'failed' },
    latestRun.exists && latestRun.failed > 0 ? 1 : 0
  );

  automationLastRunStatus.set(
    { environment: config.environment, status: 'missing' },
    latestRun.exists ? 0 : 1
  );
}

What it does: derives the tri-state automation_last_run_status{status="passed|failed|missing"} from exists/total/failed — the one piece of real logic here, everything else is a direct .set() passthrough.

scripts/run-with-results-history.js

Wraps playwright test, then copies the just-finished run over latest.json — the piece that actually maintains the "current state" pointer.

const { spawn } = require('child_process');
const fs = require('fs');
const path = require('path');

const cwd = process.cwd();

const resultsDir = path.join(cwd, 'results');
const runsDir = path.join(resultsDir, 'runs');

fs.mkdirSync(runsDir, { recursive: true });

const runId =
  process.env.AUTOMATION_RUN_ID ||
  `run-${new Date().toISOString().replace(/[:.]/g, '-')}`;

const playwrightBin = process.platform === 'win32' ? 'npx.cmd' : 'npx';

const argsFromCli = process.argv.slice(2);

const child = spawn(
  playwrightBin,
  ['playwright', 'test', ...argsFromCli],
  {
    cwd,
    stdio: 'inherit',
    shell: process.platform === 'win32',
    env: {
      ...process.env,
      AUTOMATION_RUN_ID: runId,
    },
  }
);

child.on('exit', (code, signal) => {
  const runResultPath = path.join(runsDir, `${runId}.json`);
  const latestPath = path.join(resultsDir, 'latest.json');

  if (fs.existsSync(runResultPath)) {
    fs.copyFileSync(runResultPath, latestPath);
    console.log(`[automation-results] archived run: ${runResultPath}`);
    console.log(`[automation-results] updated latest: ${latestPath}`);
  } else {
    console.warn(
      `[automation-results] run result was not found: ${runResultPath}`
    );
  }

  if (typeof code === 'number') {
    process.exit(code);
  }

  console.error(`[automation-results] playwright exited with signal: ${signal}`);
  process.exit(1);
});

What it does: shell: process.platform === 'win32' matters on Windows — spawning npx.cmd directly without a shell throws spawn EINVAL. Always exits with Playwright's real exit code so CI still fails correctly, even though latest.json gets updated either way.

12GitHub Actions

Not present in this repository

No .github/workflows/ exists yet. This is the recommended pattern for when CI is added.

A GitHub Actions job is short-lived — it starts, runs, and the runner disappears. The exporter must live somewhere that persists across runs, so it can keep serving /metrics continuously.

PatternFits
Upload results as a workflow artifactLocal learning / small teams — simplest to start with
Upload to shared storage (S3, etc.)Small production setups — exporter syncs from the same bucket on a timer
Push to an ingestion endpointProduction, multiple CI sources — exporter exposes POST /runs
.github/workflows/playwright.yml — example
name: Playwright
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - working-directory: automation/playwright
        run: npm install
      - working-directory: automation/playwright
        run: npm run test:observed
      - uses: actions/upload-artifact@v4

monitoring/prometheus/rules/api-recording-rules.yml
groups:
  - name: api-recording-rules
    interval: 30s
    rules:
      - record: api:http_requests:rate5m
        expr: sum(rate(http_requests_total[5m])) by (route, method, status_code)

      - record: api:http_requests_by_route:rate5m
        expr: sum(rate(http_requests_total[5m])) by (route)

      - record: api:http_errors:rate5m
        expr: sum(rate(http_errors_total[5m])) by (route)

      - record: api:http_error_ratio:5m
        expr: |
          sum(rate(http_errors_total[5m])) by (route)
          /
          clamp_min(sum(rate(http_requests_total[5m])) by (route), 0.001)

      - record: api:http_5xx:rate5m
        expr: sum(rate(http_requests_total{status_code=~"5.."}[5m])) by (route)

      - record: api:http_5xx_ratio:5m
        expr: |
          sum(rate(http_requests_total{status_code=~"5.."}[5m])) by (route)
          /
          clamp_min(sum(rate(http_requests_total[5m])) by (route), 0.001)

      - record: api:http_request_duration:p95_5m
        expr: |
          histogram_quantile(
            0.95,
            sum(rate(http_request_duration_seconds_bucket[5m])) by (le, route)
          )

      - record: api:http_request_duration:p99_5m
        expr: |
          histogram_quantile(
            0.99,
            sum(rate(http_request_duration_seconds_bucket[5m])) by (le, route)
          )

18Metric types refresher

A quick reference for the four Prometheus metric types — for when you forget which one to reach for.

TypeBehaviorUsed where in this repo
CounterOnly ever goes up (or resets to 0 on process restart). Never read its raw value — always wrap in rate() or increase().http_requests_total, http_errors_total — api's own metrics, §10
GaugeGoes up or down freely — represents current state, recomputed each time.All 9 automation exporter metrics, §6/§7 — because they're re-read from files on disk, never accumulated
HistogramBuckets observations into cumulative le (less-than-or-equal) ranges, plus a running _sum and _count. Quantiles computed server-side, at query time — can be aggregated across instances.http_request_duration_seconds — api's own latency metric, §10
SummaryComputes quantiles client-side, inside the process, at observation time. Cannot be meaningfully re-aggregated across instances. Not used anywhere in this repo.—

How a Histogram actually works

One Histogram definition produces several time series per label set, not one:

Each le bucket is cumulative — the le="0.1" bucket counts every request that took 0.1s or less, which is why the numbers only grow as le increases. _sum is the total of all observed durations; _count is how many observations happened — _sum / _count is the average.

How you query it in PromQL

promql
# p95 latency, aggregated correctly across every instance of the job
histogram_quantile(
  0.95,
  sum(rate(http_request_duration_seconds_bucket[5m])) by (le, route)
)

# average latency (not a percentile — just mean)
rate(http_request_duration_seconds_sum[5m])
  /
rate(http_request_duration_seconds_count[5m])
The one rule that matters — aggregate away everything except le

histogram_quantile() needs its input grouped only by le (plus whatever you deliberately keep, like route). If a label like instance or pod survives into the aggregation, you get several independent, incomplete bucket ladders instead of one true combined one — and the quantile math silently produces a wrong number. No error, no warning, just a bad p95 you'll ship into a dashboard. Always sum(...) by (le, ...) before calling histogram_quantile() — never hand it raw, un-aggregated bucket series.

Counter refresher — rate() vs increase()

  • rate(x[5m]) — average per-second rate over the window, extrapolated, handles counter resets automatically. Use for alerting and dashboards.
  • increase(x[1h]) — total increase over the window, in human terms ("how many errors in the last hour"). Same reset-handling as rate(), just scaled to absolute count instead of per-second.
Do you need to "run" a metric type?

No — there's nothing to start or run. A metric type is just which prom-client constructor you call (new Counter(...), new Gauge(...), new Histogram(...)) when defining it in code (§6, §10). Once registered, it exists and answers scrapes automatically. PromQL functions like rate() and histogram_quantile() aren't "run" either — you just type them into a query at localhost:9090/graph or the query API, and Prometheus evaluates them on the fly against whatever's already stored, no setup step required.
